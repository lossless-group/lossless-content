## Thesis

SaaS companies usually pick a vendor, often several, for each of these:

- Product marketing
- Onboarding
- User documentation
- Product walkthroughs
- Step-by-step tutorials
- Engagement analytics
- Omnichannel engagement notifications and comms
- Social features like comment boards
- Quantitative user feedback (surveys)
- Qualitative user feedback (discussion boards)
- User communities
- Public product roadmaps
- User suggestions
- Customer support tickets
- Stakeholder reporting

Agentic engineering is starting to let fast, capable organizations build tools like these in-house. Because they're common utilities, though, nobody should have to imagine, envision, design, architect, spec and product-manage all of it from scratch.

Picture a utility kit in the style of shadcn/ui or Astro Starlight for all of this. You take our opinions and the starter kit, make them your own, and contribute back.

## Open questions

- Which utilities come first, and which ones depend on each other (analytics, notifications, identity)?
- Should it work like shadcn (copy the source into your repo) or like Starlight (a configurable package)?
- How do contributions flow back once each adopter has changed their copy?

Lean is an open-source programming language and theorem prover maintained by the nonprofit Lean Focused Research Organization (Lean FRO). Its core value is combining executable programming with machine-checked formal proofs, supporting “correct, maintainable, and formally verified code” through dependent types, an extensible metaprogramming system, and a trusted kernel. [^l8bsq2]

## Value Proposition & Features

Lean targets software and mathematics where correctness matters: users can write programs, state specifications, and construct proofs checked by Lean’s kernel. [^l8bsq2] Lean 4’s self-hosting implementation and extension API support faster development, customization, and scaling to larger problems than Lean 3. [^ij0pw4]

- **Dependent type theory:** Types can encode mathematical specifications and correctness conditions. [^l8bsq2]
- **Interactive theorem proving:** Tactics and automation help construct proofs that the kernel checks. [^l8bsq2]
- **Trusted kernel:** Proof validity is ultimately checked by a small foundational core. [^l8bsq2]
- **General-purpose programming:** Lean supports executable functional programs alongside formal proofs. [^l8bsq2]
- **Extensibility:** Lean 4 exposes a rich extension API for custom syntax, elaboration, tactics, and tooling. [^ij0pw4]
- **Self-hosting:** Lean 4 is implemented in Lean, enabling rapid compiler and feature development. [^ij0pw4]
- **Mathematical libraries:** The surrounding ecosystem includes large formalization projects such as Mathlib. [^l8bsq2]
- **Proof automation:** Recent releases continue expanding automation for bit vectors, characters, finite types, and other domains. [^yc7p7m]

# History and Origin Story

Development of Lean 4 began in 2018, and Lean 4.0 was released on September 8, 2023. [^ij0pw4] Leonardo de Moura and Sebastian Ullrich launched the Lean Focused Research Organization in July 2023 within Convergent Research, with support from the Simons Foundation International, Alfred P. Sloan Foundation, and Richard Merkin. [^ij0pw4]

## Competitive Landscape

### Who it's for, who it's not for

Lean is suited to mathematicians, formal-methods researchers, educators, and software or hardware engineers who need machine-checked specifications and proofs. [^l8bsq2] Its extensibility and executable programming model also suit teams building domain-specific verification tooling. [^ij0pw4]

Lean is not an obvious fit for projects that need only conventional application development and have no requirement for formal guarantees, because formalization introduces additional modeling and proof work. [^l8bsq2]

### Viable Alternatives

- **Coq:** A mature proof assistant based on dependent type theory and widely used for formal verification.
- **Isabelle/HOL:** A higher-order logic proof assistant with extensive automation and engineering tooling.
- **Agda:** A dependently typed programming language and proof assistant emphasizing interactive development.
- **F\*:** A dependently typed language focused on program verification and executable specifications.
- **HOL4:** A theorem prover based on higher-order logic, used for machine-checked mathematics and verification.
